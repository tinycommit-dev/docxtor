# Extension contribution points

Everything an extension can add, with the places it shows up. The [extensions guide](index.md) starts with a first extension and the context every `activate` function gets.

## Contribution points

| Point | Where it shows up |
|---|---|
| `commands` | The command palette (⇧⌘P or ⌥/), the shortcut you give it, and menus. `icon` names an icon. `when` hides it when it doesn't apply. With `ai: true` the assistant can run it too (only for commands that need no further input). |
| `cautions` | A warning before a risky action (DESIGN.md, Risky actions): `{ id, kind, title, impact?, confirm?, permanent?, danger? }`. With `kind: "ask"` the host asks first, saying what changes (the button names the action, Cancel has the focus, and `permanent` adds "This can't be undone."); with `kind: "undo"` it does it, then shows a notice with Undo (not when the command returns `false`). An `id` that is a command's is asked about wherever the command runs from; any other id is a button in a dialog, which asks with `ctx.ask(id, ...args)`. Text can be a function of the arguments, for names and counts. Docxtor's own are in `packages/editor/src/builtins/cautions.ts` (`docxtor.cautions`, always on) and `web/src/cautions.ts`. |
| `toolbar` | A button in the Text, Paragraph or Insert group, or in an Extensions group at the end. `isActive(format)` shows it pressed. |
| `menus` | A menu of the menu bar (`file`, `edit`, `view`, `insert`, `format`, `tools`, `extensions`, `help`), the right-click menu (`context`), or a submenu by its id. See [Menus](#menus) below. |
| `panels` | A tab in the app's navigator. `render(el)` fills it once; `onShow()` runs each time it's shown. A panel with `tool: true` (the accessibility check, the dictionary) has no tab until something shows it with `sidebar.show(id)`; then it gets a tab with a close button. |
| `exporters` | Under "Download a copy", and `editor.export(id)` for embedders. Return bytes, a string or a Blob. Docxtor's own are separate extensions: `docxtor.formats` (Word, Markdown, plain text) and `docxtor.format.odt`, `docxtor.format.rtf`, `docxtor.format.html` and `docxtor.format.epub` (`packages/editor/src/builtins/export-formats.ts`, one engine call each: `doc.exportOdt()` and so on), so any of them can be turned off. |
| `importers` | Lets Docxtor open more file types: File, Open, the Files panel's Import, a dropped file and `editor.open()` for embedders. Return `{ markdown }` or `{ docx }` (with a `notice` to tell the person what the conversion left out); Docxtor turns it into a new .docx. Docxtor's own: `docxtor.formats` (Markdown, plain text) and `docxtor.open.odt`, `docxtor.open.rtf`, `docxtor.open.html`, `docxtor.open.doc` and `docxtor.open.xml` (see [Opening files](files.md#opening-files)). |
| `templates` | File, New from a template, and the start screen. Return `{ markdown }` or `{ docx }`. |
| `themes` | The Theme picker. A base (`light` or `dark`) plus token overrides; [DESIGN.md](../../DESIGN.md) lists the tokens. |
| `ai.providers` | The model list in AI settings. `connect()` returns a `Conversation` that the assistant's agent loop drives. |
| `ai.tools` | Extra tools for the assistant. Names can't replace Docxtor's own tools. |
| `contentControls` | Kinds of content control, `{ kind, label?, render?(elements, control), edit?(api) }`. `kind` is one of the engine's (`checkbox`, `date`, `dropDown`...) to take over how that kind is drawn and edited, or the control's `w:tag` for a kind of your own: Docxtor writes it as a rich text or plain text control with that tag, so Word keeps the content. `render` is called after a control is drawn with the elements it covers and what it shows (`ContentControlInfo`); `edit` is called when the control is clicked, with `control`, `anchor`, `set({ text?, checked?, index?, date? })`, `exec(ops)` and `popover(content)`. Docxtor's own controls (the tab, the check box, the lists and the calendar) are in `packages/editor/src/ui/controls.ts`; the commands, menus and protection strip are the built-in extension `docxtor.controls`. |
| `tableDesigns` | Designs for the Table design gallery (Format, Table, Table design…) beside Word's built-in ones. Each is `{ id, label, xml, group? }`: `xml` is one `w:style` of type `table`, written as Word writes a table style (conditional formatting in `w:tblStylePr`, so the header row, banded rows and the options of `w:tblLook` all work). The engine draws the tile from it (`Engine.tableDesignPreview`) and, when a table gets the design, adds the style to the document (`{"op":"table_design","at":…,"definition":xml}`) unless the document already has a style with that id. A design the engine can't read is left out. Docxtor's own designs are the engine's (`table_designs`), and the commands and gallery are the built-in extension `docxtor.tableDesign`. The other table commands (`table.properties`, `table.splitCells`, `table.splitTable`, `table.insertCells`, `table.deleteCells`, `table.distributeRows`, `table.sort`, `table.formula`, `table.convertToTable`, `table.convertToText`, `table.textDirection.*` and `insert.tableDialog`) are the built-in extension `docxtor.tableTools`; each is a command, so an extension can run it, bind a key to it or place it in a menu. |
| `chartPalettes` | Colour palettes for the Change colors gallery of the Edit chart dialog, beside Word's own (colourful 1 to 4, monochromatic 1 to 13). Each is `{ id, label, colors }`: `colors` is a list of `RRGGBB` or `scheme:accent2` (optionally `scheme:accent2:lumMod=60000:lumOff=40000`, so the chart follows the document's theme) in series order; the list repeats for more series, and a pie or a chart with varied colours takes them by point. Choosing one sets the colours of the series; the chart keeps them as ordinary series colours in the file. Words from the extension are shown as given. |
| `documentThemes` | Themes for Design, Themes, Colors and Fonts. With `colors` and `fonts` it is a whole theme (a tile in the Themes gallery); with only `colors`, a colour scheme (Colors); with only `fonts`, a font pair (Fonts). `colors` holds hex values by slot (`dk1`, `lt1`, `dk2`, `lt2`, `accent1` to `accent6`, `hlink`, `folHlink`); slots left out keep the document's. See [Themes and style sets](document-look.md#themes-and-style-sets). |
| `styleSets` | Style sets for Design, Style set: `{ id, label, description?, styles?, spacing? }`. `styles` is one or more `w:style` elements as XML; choosing the set rewrites the formatting of the styles it names (and adds the ones the document lacks) and sets the paragraph spacing of the document defaults. Docxtor's own sets have no `styles`: the engine has them by `id`. |
| `icons` | One icon (`id` plus SVG) for commands, menus and the toolbar to use by id. Registering one of Docxtor's ids (`bold`, `print`, `search`…, listed in `packages/editor/src/ui/icons.ts`) replaces it while your extension is on, whichever icon pack is chosen. It is the way to restyle a single icon. |
| `iconPacks` | A named set of icons (`{ id, label, icons }`) that people choose between under View, Icons. See [Icon packs](document-look.md#icon-packs). |
| `fonts` | A font family in the font menu (`family`, plus a `stylesheet` URL or font `faces`). `substitutes` names Word fonts it can stand in for with matching metrics; `category` picks the fallback while it loads; `menu: false` keeps a pure stand-in out of the menu. Fonts load only when text uses them. |
| `storage` | A section in Files, with addresses like `#/storage/<id>/path.docx`. Same shape as the Library: `list`, `read`, `write`, `mkdir`, `rename`, `remove`, `exists`. |
| `citations.styles` | A choice in the Citations panel's style picker. With `csl` (the XML, or a function that returns it) it is a CSL 1.0.2 style that Docxtor's own processor formats. See [Citation styles and sources](merge-citations-fields.md#citation-styles-and-sources). |
| `citations.sources` | A button under "Add a source" in the Citations panel that opens a dialog fitted to the provider: a search box (`search`) or an input for something to look up or read (`resolve`). |
| `citations.libraries` | A list of sources kept apart from any document (Word's master list). The Citations panel's "Shared list…" dialog copies sources between it and the document. See [Shared lists and quick parts](document-look.md#shared-lists-and-quick-parts). |
| `snippets.stores` | A place saved quick parts and AutoText are kept: `list()` and `save(all)`. Insert, Quick parts saves into one and lists all of them. See [Shared lists and quick parts](document-look.md#shared-lists-and-quick-parts). |
| `pictures.sources` | A line under Insert, Image ("From your computer…", "From a URL…", a stock photo library…). `pick({ ui, signal })` shows whatever it needs and resolves with `{ bytes, name, type?, alt? }` (or a list of them), or null when the person gave up. See [Picture sources](document-look.md#picture-sources). |
| `spelling.dictionaries` | A source of Hunspell dictionaries (`.aff` and `.dic`) for Docxtor's spelling checker. It names the `languages` it covers and returns a dictionary from `load(lang)`, or null. Several can be on at once; for a language, the latest registered one that has it wins. See [Spelling and grammar](language.md#spelling-and-grammar). |
| `spelling.languageDetectors` | Tells what language a paragraph is in, for Detect language automatically (Proofing options): a paragraph in the document's language is checked in the language its words are in. `detect(text)` returns `{ lang, confidence }` (0 to 1) or null, at once or as a promise. Asked latest first; the first answer at least 0.6 sure wins; one that throws is reported and skipped. Docxtor ships two: the browser's own (Chrome's LanguageDetector, only when its model is already on the computer) and one that works offline from common words, for English, Spanish, French, German, Italian, Portuguese and Dutch. |
| `fields` | A field type: a name in Insert, Field with the form it shows (`options`) and, optionally, `evaluate(call)` that works out the result. See [Fields](merge-citations-fields.md#fields). |
| `clipboard.converters` | A reader for a format on the clipboard (or in a drop), by MIME type: `{ id, label, mime, priority?, convert(input) }`. `convert` gets the format's data as text, the other formats (`get(type)`), the engine and `fetchImage`, and returns `{ fragment }` (what `Engine.htmlToFragment` and `Engine.rtfToFragment` make; it pastes with the person's choice of source or merged formatting), `{ markdown }` or `{ text }`, or null to leave the paste to the next converter. Converters run from the highest priority down. Docxtor's own are built in (`docxtor.fragment` 100: its own format, also carried in HTML; `docxtor.html` 50: Word, Google Docs and web pages, with pictures from `data:` addresses and fetched ones; `docxtor.rtf` 40; `docxtor.text` 10), so an extension can add a format such as `application/x-my-app` or put a converter above Docxtor's. Paste special lists every converter whose format is on the clipboard. |
| `views` | A way to show the document, under View, Layout and in the palette (`view.mode.<id>`). `{ id, title, icon?, description?, order?, layout?, width?, maxWidth?, margin?, marginLeft?, marginTop?, readOnly?, className?, enter? }`. `layout` is `pages` (the default) or `continuous` (one unbroken sheet with no page breaks, headers or footers); for a continuous layout `width` is `page` (the first section's text width) or `window` (fits the window, up to `maxWidth`, default 760 px at 100%), and `margin`, `marginLeft` and `marginTop` are the margins in px. `readOnly` locks the text while the view is on. `className` goes on the editor's page area (`.editor-host`) with `view-<id>`, for the view's own CSS. `enter({ root })` runs when the view starts and returns a function that runs when it ends. One view is on at a time (`editor.setView(id)`, `editor.view`, the `view` event); a view whose extension is taken away falls back to the print layout. Docxtor's own (`print`, `pageless`, `reading`, `outline`) are registered the same way by the built-in extension `docxtor.views` (`packages/editor/src/builtins/view.ts`), which also holds the zoom commands, folding headings, the Outline view's commands (`outline.*`, available only in that view), compact mode (`view.compact`) and the Navigation pane panel (`navigation`). |
| `hyphenation` | A hyphenator: `{ id, label, languages, hyphenate(word, lang) }` returns where a word may break, for Hyphenate manually. The latest registered one that covers the language and has an answer wins. See [Hyphenation](language.md#hyphenation). |
| `readings` | A reading provider: `{ id, label, languages, reading(text, lang) }` returns how East Asian text is read (hiragana for Japanese, pinyin for Chinese), for the Suggest button of the Phonetic guide box. The latest registered one that covers the language and has an answer wins. See [Readings](language.md#readings). |
| `thesaurus` | A source of synonyms for Tools, Thesaurus: `{ id, label, languages, lookup(word, lang) }`. Every one that serves the language answers; the panel lists them by source. See [Thesaurus](language.md#thesaurus). |
| `inspectors` | A check for Inspect document (Tools): `{ id, label, inspect(ctx), remove?(ctx) }`. All run; what the person chooses to remove goes in as one undo step. See [Inspect document](files.md#inspect-document). |
| `comparers` | A way to compare two versions for Compare documents and Combine documents: `{ id, label, compare, redline?, combine? }`. The latest that can do the job is used. See [Compare and combine](files.md#compare-and-combine). |
| `grammar` | A grammar or style checker. It names the `languages` it covers and finds problems in a batch of paragraphs with `check(request)`. Any number can be on at once and their findings are merged. See [Spelling and grammar](language.md#spelling-and-grammar). |
| `mailMerge.dataSources` | A place a list of recipients comes from, under Mailings, Select recipients: `{ id, label, icon?, note?, pick({ ui, signal }) }`. `pick` shows what it needs and resolves with `{ columns, rows, name? }`, or null when the person gave up. Docxtor's own are a CSV file and an Excel file. See [Mail merge](merge-citations-fields.md#mail-merge). |
| `mailMerge.mailSenders` | A way to send the messages of an email merge (Mailings, Send email messages): `{ id, label, icon?, note?, formats?, warnAbove?, limitNote?, summary?(n), send(messages, ctx) }`. Docxtor's own save a .zip of .eml files and open the person's mail app. See [Mail merge](merge-citations-fields.md#mail-merge). |
| `mailMerge.labelProducts` | A kind of label sheet for the Labels dialog: a vendor, a name and where the labels are on the page (`{ id, vendor, name, unit?, pageWidth, pageHeight, top, left, labelWidth, labelHeight, pitchH, pitchV, across, down }`). Docxtor ships Avery's common sheets. |

## Menus

Every menu line runs a command, so a command added to a menu also gets its shortcut and a place in the palette:

<!-- example: ext-menus -->
```ts
ctx.commands.register("acme.wordGoal", () => openGoal(), { title: "Word goal…", category: "Tools" });
ctx.menus.register({ menu: "tools", command: "acme.wordGoal" });

// A submenu: an entry that names it, then items whose `menu` is its id.
ctx.menus.register({ menu: "extensions", submenu: "acme/menu", title: "Acme" });
ctx.menus.register({ menu: "acme/menu", command: "acme.shout" });
```

- Items with the same `group` sit together between separators. Groups are sorted by name, and Docxtor's own are numbered (`1_new`, `2_open` and so on), so `"2_zz"` puts yours after the open commands. `order` sorts within a group. Items without a group go last.
- While a command's `when` returns false, its menu line is greyed out rather than hidden.
- A command's `icon` (an icon id or SVG) shows at the start of its menu line; menu items can set their own. A command with `toggled: () => boolean` shows a check mark there while it's on ("Show ruler").
- `shortcutHint: "Mod+C"` shows a shortcut the browser handles itself without binding it.
- Docxtor's own menu items are registered in `packages/editor/src/builtins/menus.ts` and `web/src/builtins.ts`.

## Shortcuts

Write shortcuts as `Mod+Shift+P`, where `Mod` is ⌘ on a Mac and Ctrl elsewhere. Letters and digits match the physical key, so `Alt+/` still works on a Mac keyboard where ⌥/ types ÷. When two commands claim the same shortcut, the first one registered wins. Built-ins register first, so an extension can't take over ⌘B. In a text field, the field keeps its own editing keys (⌘Z, ⌘A, ⌘C and so on).
